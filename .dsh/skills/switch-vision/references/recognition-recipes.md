# Switch 2 视觉识别配方（实测数值）

所有数字都来自 1920×1080 截图（OBS `GetSourceScreenshot`）在真实存档上的实测。
换分辨率、换 UI 皮肤、游戏大版本更新后必须重新标定。

## 1. 画面与 OCR 基础

- 画面：`OBS obs-websocket v5`，`GetSourceScreenshot`，PNG 用于分析，JPEG(q=90) 用于连续取帧。
- OCR：`vision/bin/ocr_vision`（macOS Vision，Swift 编译）。用法 `ocr_vision <image> [lang]`，
  `lang` 为逗号分隔的识别语言，缺省 `zh-Hans,en-US`。
- **数字类内容必须传 `en-US`**：带中文模型时 `0.5` 会被读成 `回5`。
- OCR 前处理：灰度 → `INTER_CUBIC` 放大 → 白色 padding（`copyMakeBorder`，28px）。
- 单帧 OCR 约 0.3–0.6s；一格 badge+count 约 0.6–1s。

## 2. 模式门禁（`state_reader.py`）

模式：`HOME / WORLD / MODAL / WAREHOUSE / BACKPACK / UNKNOWN`。判定顺序：

1. **HOME 优先**：系统 UI 小模板 `sys_battery`、`sys_pad_battery`
   （ROI `home_status_search=[0.865,0.050,0.135,0.090]`，阈值 0.75）。
   HOME 帧得分 0.99/0.99，所有游戏内帧 ≤0.46。**不先判 HOME 会把主界面误判成 WORLD。**
2. **WORLD 安全判定**：HUD 日期行 OCR（ROI `datetime=[0.833,0,0.167,0.116]`）
   必须读出「春月16日」这类文本 + 体力/风向图标 → `world_is_safe()`。
   日期行是可靠锚点：它在 Switch 主界面和系统菜单永远不会出现。
3. `MODAL` 用模态框模板（`modal_*`）；`WAREHOUSE`/`BACKPACK` 用标题模板 + OCR 标题文本。
4. 任何非目标模式一律 `stop_all()` + 存快照后退出，**绝不盲发按键**。

## 3. 网格几何（`config.yaml` 的 ROIs + `grid_reader.cells()`）

仓库界面：左侧背包 8×4，右侧仓库 6×4；仓库有 9 页（翻页圆点 ROI `warehouse_pages`）。

| ROI | 值 | 换算（1920×1080） |
|---|---|---|
| `warehouse_left_grid` | `[0.07760, 0.24815, 0.44167, 0.41111]` | x0=149, y0=268, 8×106 × 4×111 |
| `warehouse_right_grid` | `[0.59583, 0.24815, 0.33125, 0.41111]` | x0=1144, y0=268, 6×106 × 4×111 |
| `backpack_grid`（X 键背包界面） | `[0.0625, 0.2315, 0.4661, 0.5000]` | 未重新标定，沿用 |

- **真实格子间距 106×111 px，卡片 93×92 px**。按 ROI 均分（111.87×116.25）会让最后一列累计漂移约 40px。
- `cells()` 按 ROI 等分出 `rect=(x1,y1,x2,y2)`；**所有相对裁剪都从这个 rect 算**。
- 占用判据：cell 中心区域（18%–82%）灰度标准差 > `OCCUPIED_STD=18`。
- 选中判据：cell 边缘环（`SELECT_RING_FRAC=0.12`）中"蓝色像素"占比 > 0.18
  （蓝通道比红通道高 25 且 >140）。边框检测偏弱，**不要单独依赖选中检测做导航**。

## 4. 图标指纹（`grid_reader.patch()` + `ItemCatalog`）

- 取 cell 的 `ICON_CROP=(0.06,0.06,0.94,0.94)` → 缩放到 `PATCH_SIZE=24×24`。
- 遮罩（**四角全遮，因为学习时格子是选中态**）：
  - 顶部 32%（角标条）：`mask[:24*0.32, :] = 0`
  - 左下角：`mask[24*0.62:, :24*0.30] = 0`
  - 右下角（数量）：`mask[24*0.68:, 24*0.55:] = 0`
- 相似度：遮罩内逐通道去均值后的余弦相似度。
- 匹配：`>=0.86` 直接命中；`>=0.78` 且 **最佳−次佳 ≥0.08** 也命中（质量变体分数会到 0.81）。
- 合并：`MERGE_THRESHOLD=0.95`；否则**同名物品按变体合并**（不同颜色鸡蛋等），
  每个物品最多 `MAX_ICON_SAMPLES=5` 个样本（目录合并后允许到 8）。
- 目录结构（`vision/data/item_catalog.json`）：

```json
{
  "version": 2,
  "items": {
    "item_001_粉蝶花种子": {
      "name": "粉蝶花种子",
      "aliases": [],
      "category": null,
      "description": null,
      "stars": {"0.5": {"price": 90}},
      "base_price": 90.0,
      "icons": [{"shape": [24,24,3], "b64": "...", "mask_shape": [24,24], "mask_b64": "..."}],
      "seen": 2
    }
  }
}
```

`icons` 里是 uint8 base64（不是浮点数组，否则文件会到 MB 级）。

## 5. 角标（品质星级）配方

- **品质共 14 档**：0.5, 1.0, 1.5, …, 7.0（0.5 步进）。**品质 7 = 彩虹星**（实测 24/24）。
- 裁剪 `BADGE_RECT=(21,-13,64,29)`，相对 cell 左上角，**按整帧绝对坐标裁**（允许负偏移，角标溢出格子）。
- 星图标 `STAR_RECT=(-7,-14,29,31)`，HSV 判档：
  - 彩色像素 = `S>70 & V>110`
  - `blue_frac >= 0.60` → blue；`purple_frac >= 0.50` → purple；
    `warm >= 0.20 & green >= 0.15` → rainbow
  - rainbow 直接返回 7.0（不再 OCR）
  - **blue 覆盖所有非 rainbow 品质**（蓝星也可能是 5.0），不要把颜色当值域过滤器
- OCR 变体（依次尝试，命中即停）：灰度 + 反色两遍 × 放大 6/4/3 × 白边 28 → `en-US`。
- 文本归一化：`S→5, O/o/D→0, I/l/|→1, Z→2, B→8, g/q→9`，再去掉非数字，按
  `{"05":0.5, "1":1.0, "15":1.5, "2":2.0, "25":2.5, ..., "7":7.0}` 对齐；
  兜底 `parse_star_value()`（限制 0.5–7.5）。
- **模板兜底**（`badge_templates.py`）：Vision 读不出单字形时，用字形模板匹配（阈值 0.86）。
  字形提取：
  1. 去掉"行内暗像素占比 >65%"的横线（卡片上边框）；
  2. 裁掉左侧 10%（星星残影）；
  3. Otsu 反色 + 连通域，取面积最大的 2 个连通域并成外接框；
  4. **只按高度归一化**到 28px，居中贴到 40×28 画布（"1" 不会被拉宽成 "0.5"）。
  扫描时 `harvest=True` 会把成功识别的字形存入模板池（每值最多 12 个、相似度 0.97 去重）。
- **"无角标"是合法状态**：瓶子、靴子、鱼骨、空罐、纪念币等物品没有品质角标。
  `badge.present=False` 与"读不出"分开；这类物品售价 = 基准价（按 0.5 档）。

## 6. 数量配方

- 裁剪 `COUNT_RECT=(44,60,56,42)`（溢出格子右下角），**原始 BGR 不转灰度**，放大 4x（再试 5x），`en-US`。
- 取数字串转 int；**空结果 ⇒ 1**（Vision 读不到单个 "1"，而 1 是默认堆叠）。
- 实测：2 位数 95%，加"空⇒1"规则后 97.8%+，整仓 222/222。

## 7. 价格模型（`item_prices.py`）

来源：GameWith「品質の上げ方と効果」（<https://gamewith.jp/bokumono-grabaza/515215>），已用实机价验证。

| 品质 | 倍率 | 品质 | 倍率 |
|---|---|---|---|
| 0.5 | 1.00 | 4.0 | 1.40 |
| 1.0 | 1.05 | 4.5 | 1.50 |
| 1.5 | 1.10 | 5.0 | 1.60 |
| 2.0 | 1.15 | 5.5 | 1.80 |
| 2.5 | 1.20 | 6.0 | 2.00 |
| 3.0 | 1.25 | 6.5 | 2.50 |
| 3.5 | 1.30 | 7.0 | 3.00 |

`售价 = round(0.5★基准价 × 倍率)`。实机反推全部得到整数基准价：
铁矿石 7★=450→150、橄榄石 7★=4500→1500、香草沙拉 7★=411→137、月落草 7★=243→81。

目录只存 `base_price` + 见过的 `stars`（审计用），`price_for(item, star)` 现算。

## 9. 导航拓扑与验证（`learn_targets.py` / `learn_prices.py`）

实测拓扑：

- 每次打开仓库：**光标复位到背包 (0,0)，页码复位到 1**。
- 背包内：`UP/DOWN` 同列移动，`RIGHT/LEFT` 同行移动；第一行再 `UP` 会切到其他面板（别碰）。
- 从背包最右列（col 7）再 `RIGHT` → 进入右侧仓库网格**同一行**；仓库网格 6 列，`RIGHT` 到最后一列会**换行**。
- 页翻：`R` 下一页，`L` 上一页；分页圆点 OCR 可读出 `{page, total}`。
- 确定性进入第 N 页右网格：`B` 关 → `A` 开 → `R`×(N-1) → `RIGHT`×8 → 光标在 (0,0)。

验证式走位（`press_verified`）：

1. 按键前后各截一帧（JPEG）。
2. 对每个格子取**边框环**（`RING=10px`：上下左右各 10px 条带）的灰度签名，算平均绝对差。
3. 排除"旧位置"后，变化最大的格子应当是"预期的新位置"；否则视为丢帧/错走，重按（最多 3 次）。
4. 判定阈值：变化分 > 6.0 且 > 次高分 ×1.15（太严会频繁重试，实测 1.4 过严）。

补价格时更稳的验证：**用物品名验证位置**（期望名字来自上次盘点结果），名字不符就重开重来。

## 11. 已知限制

- 换分辨率 / UI 缩放 / 游戏版本更新 → 所有裁剪框与 ROI 需要重新标定（用标注帧验证）。
- 紫色星档样本少（品质 4–6.5 多为蓝星，紫色未验证）。
- 选中框检测偏弱（蓝色环判定），不要用于精确定位；导航请用验证式走位或名字校验。
- 夜晚/滤镜不影响仓库 UI（UI 不受光照影响），但世界 HUD 的 HSV 会漂移（见 `walk_to_storage.py` 的色相窗口）。
